## Bridge binary symlink resolution during install (#479)

- Landed: `ConfigInstaller.installBridgeBinary` now prefers `Helpers/morrow-bridge` (and `execDir/morrow-bridge`), resolves symlinks via `resolvingSymlinksInPath()` and verifies `.typeRegular` before `copyItem`, cleans up stale `<dest>.tmp.*` entries (including broken symlinks), and unlinks `tmpPath` on failure with atomic `rename` fallback.
- Where: `macos/Sources/Morrow/ConfigInstaller.swift`, `macos/Tests/MorrowTests/BridgeBinaryInstallerTests.swift`.
- Verified: `BridgeBinaryInstallerTests` (6 passed, 0 failed), `MorrowFolderPrivacyTests` (9 passed, 0 failed), `ConfigInstallerTests` (74 passed, 0 failed), `./scripts/ci/verify-local.sh` passed, `./macos/build.sh` built `Morrow.app`, and launching `Morrow.app` updated `~/.codeisland/codeisland-bridge` (`0700` regular file, zero `.tmp.*` entries) with `/tmp/morrow-501.sock` active.
- Left open: None; PR opened on `fix/#479-bridge-symlink-install`.
- Why: `macos/build.sh` creates `Helpers/codeisland-bridge` as a relative symlink to `morrow-bridge`, so `FileManager.copyItem` copied a dangling symlink to `~/.codeisland/codeisland-bridge.tmp.<PID>`, causing `replaceItemAt` to fail and leaving pre-rebrand bridge binaries stuck on `/tmp/codeisland-*.sock`.
